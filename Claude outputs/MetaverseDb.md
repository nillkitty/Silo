## Metaverse Database (`y.db`)
The Metaverse database holds the normalized, aggregated view of your connected data: objects composed from one or more World sources, joined and projected together under a shared schema.

### Schema tables
| Table | Description |
|--|--|
| `MvType` | A meta-type — `Name`/`DisplayName` and `Flags`. |
| `MvTypeHierarchy` | An inheritance or inclusion relationship between two meta-types (`Subject`/`Target`, `Relation`). |
| `MvAttribute` | A field on a meta-type — `Name`/`DisplayName`, the .NET `Type`, `Syntax`, an optional `DefaultValue`, the `CombinatorType` used to combine multiple values, and `Flags`. |

### Object tables
| Table | Description |
|--|--|
| `MvObj` | A metaverse object instance — its `Type`, unique `Key`, `Created`/`Modified` timestamps, a `LocalUri`, and its field values (stored as a flexible dictionary rather than fixed columns). |
| `Connector` | Links an `MvObj` to a single World's representation of it — `World`/`WorldType`, the World-side `Key` and `AbsolutePath`, and how the link came to be (`LinkedVia`) and when (`LinkedAt`). An `MvObj` can have more than one `Connector`, one per contributing World. |
| `ConnectorPending` | Pending changes queued against a `Connector`: a `PendingDelete`, a `PendingUpdate` (a set of properties to change), and/or a `PendingCreate` (for a newly provisioned object — its `ContainerKey`/`NativeType`/`AbsolutePath`/`PartialPath` and properties), plus a `Failures` count and the `LastFailure`/`LastFailed` if the pending change has been failing to apply. |

For every connected object, the engine tracks up to three representations of its state: what the source last reported (the **Import Hologram**), the desired state generated by outbound sync rules but not yet confirmed (the **Pending Export Hologram**), and the state the sync engine believes the target has actually accepted (the **Base/Export Hologram**).

### Enums
**`TypeRelation`** — `Inheritance` (subject inherits target as a base type) or `Auxiliary` (subject includes target as an auxiliary type).

**`MvTypeFlags`** — `None`, `Auxiliary` (the type only supplies supplemental fields for other types that reference it).

**`MvAttributeFlags`** — `None`, `Nullable`, `Multivalue`, `Indexed`, `Anr`, `Key`.

**`LinkedVia`** — how a `Connector` came to exist: `None`, `Manual`, `Join` (via [Join rules](WorldDb)), `Provision` (via [Provisioning rules](WorldDb)), `Projection` (via [Projection rules](WorldDb)).

**`MvObjFlags`** — `None`, `Tombstone`.
